# 成本核算 · 第六周

> 一句话结论：**训练几乎不花钱（本机 RTX 4060 Laptop，约 1 元），推理服务器约 20 元/月，全年 ≈ 240 元。**
>
> 价格来源：2026-10-22 检索的阿里云公开报价。活动价随时浮动，**下单前以控制台订单页为准**。

## 1. 先说一个必须诚实的前提：你没在云上训练过

翻了一遍前几周的实验记录：

- 第四周 `README.md`：**「硬件：RTX 4060 Laptop 8GB」**
- 第四周 `实验报告.md`：**「RTX 4060 Laptop 8GB · 单种子 seed=42 + 三种子复核」**
- 第二周 `logs/main224b.log`：`[all done] 总用时 24.0 min`
- 第二周 `logs/bnz.log` / `res64.log` / `eff_bnz.log`：`[done] 阶段B 用时 6.8~8.1 min`

也就是说，**前五周的所有训练都跑在你自己的笔记本显卡上，没有产生过任何云服务费。**

所以"GPU 训练用了多少小时 × 单价"这个问题，有两种诚实的算法，我两个都给：

| 算法 | 回答的问题 | 结果 |
|---|---|---|
| **A. 本机折算** | 这 6 小时真实花了我多少钱（电费 + 硬件折旧） | **≈ 0.9 元** |
| **B. 等效云价** | 如果这 6 小时搬到云上跑，要多少钱 | **≈ 14 元**（T4 按量） |

两个数字都要会算：A 是你实际的成本，B 是你回答"上云划不划算"这个决策问题的依据。

### 2.1 有日志可查的部分（硬数据）

| 周次 | 证据 | GPU 时间 |

### 2.3 合计，以及那个必须加的系数

```
可查证 + 估算 = 2.0 + 0.8 + 0.3 + 0.5 + 0.1 ≈ 3.7 GPU 小时
```

但**这个数是偏低的**，因为它只算了"跑成功的那一次"。真实训练里还有：

- 超参调错、OOM、数据路径写错，跑一半重来
- 第四周为了验证种子噪声，同一个配置跑 3 个种子
- 第二周 `main224.log` 里那几行 `OpenBLAS error: Memory allocation still failed` —— 就是崩过一次

工程上一般给 **1.5~2× 的调试系数**。取 1.5：

> **GPU 训练总时长 ≈ 3.7 × 1.5 ≈ 5.5 小时，取整记 6 GPU 小时（区间 4~8）**

## 3. 算法 A：本机折算（你真实花掉的钱）

### 3.1 电费

RTX 4060 Laptop 的 TGP 上限是 115W，训练时实测一般落在 60~90W；加上 CPU、屏幕、散热，整机按 **150W = 0.15 kW** 算。

```
6 h × 0.15 kW          = 0.9  kWh
0.9 kWh × 0.55 元/度   = 0.50 元
```

（居民阶梯电价全国大致 0.50~0.62 元/度；如果是实验室/商用按 1.0 元/度，也就 0.9 元。）

### 3.2 硬件折旧

笔记本整机按 **5 年直线折旧**。假设整机 8000 元，其中 GPU 相关成本按 35% 估算：

```
GPU 年折旧 = 8000 × 35% / 5 = 560 元/年
每小时折旧 = 560 / 8760     = 0.064 元/小时
6 小时折旧 = 0.38 元
```

> 注：这个算法假设"显卡只用来训练"，其实它还打游戏、看视频，所以严格说还要按使用率摊 —— 那样数字更小。0.38 元已经是个偏保守的上界。

### 3.3 算法 A 结论

| 项 | 金额 |
|---|---|
| 电费 | 0.50 元 |
| 硬件折旧 | 0.38 元 |
| **训练总成本** | **≈ 0.9 元** |

**这就是真相：在自己的 4060 上训一个 5 类分类模型，电费可以忽略不计。**
训练真正的成本是**你的时间**，不是钱。

## 4. 算法 B：等效云价（如果搬到云上）

同样的 6 GPU 小时，放到阿里云 GPU 实例上（按量付费，精确到秒）：

| 实例 | GPU / 显存 | 按量单价 | 6 小时 | 说明 |
|---|---|---|---|---|
| **gn6i**（T4） | T4 / 16GB | ≈ 2.28 元/小时 | **13.7 元** | 入门推理卡，训这种小模型够用 |
| gn7i（A10） | A10 / 24GB | ≈ 4.45 元/小时 | 26.7 元 | 性能过剩，不必 |
| gn6v（V100） | V100 / 16GB | ≈ 4.24 元/小时 | 25.4 元 | 老卡，性价比不如 T4 |
| gn6i **抢占式** | T4 / 16GB | ≈ 0.7~1.4 元/小时 | 4.2~8.4 元 | 便宜但**随时被回收**，只适合能断点续跑的离线任务 |

> 各来源给的按量单价在 1.87~3.55 元/小时之间浮动（地域、活动、是否含 drive 预装都会影响）。
> 取 2.28 元/小时作为 T4 的代表值。

**别忘了附加项**——这是新手最容易漏的：

| 附加项 | 单价 | 6 小时（按开 3 天算） |
|---|---|---|
| 系统盘 100GB ESSD Entry | 0.35~0.5 元/GB/月 | ≈ 1.7 元 |
| 公网 IP / 带宽（按流量 0.8 元/GB） | 传几个 GB 数据集 | ≈ 3 元 |
| 数据集下载出网流量 | — | 忽略（本来就下过） |

> ### 算法 B 结论
> **云上重跑这 6 小时 ≈ 14 元（T4 按量，含附加项约 18 元）**

### 4.1 这个对比说明了什么

| | 本机 4060 | 云上 T4 |
|---|---|---|
| 6 小时训练 | 0.9 元 | 14 元 |
| 前期投入 | 笔记本已买 | 0 |
| 速度 | 4060 比 T4 略慢，但差不太多 | — |
| 显存 | 8GB | 16GB（更宽裕） |
| 适合场景 | 反复迭代、调 bug | 一次性的大训练、本机显存不够时 |

**结论：你这个规模（5 类、64px、ResNet50、几小时）完全不该上云训练。**
上云的真正理由只有两个：① 本机显存不够；② 要跑几天几夜、不能占着自己的机器。

## 5. 算法 C：推理服务器（这是真正每月要付的钱）

### 5.1 先看清服务的真实胃口

第五周压测的实测数字（本机）：

| 指标 | 值 |
|---|---|
| QPS（100 并发 × 1000 请求） | **356.4 req/s** |
| 单请求 P50（并发 1） | 12.2 ms |
| 纯推理 | 7.7 ms/张 |
| 运行时 | ONNX Runtime CPU（**不需要 GPU**） |
| 模型 | 90MB ONNX |
| 常驻内存 | ≈ 300MB（单进程） |

**关键判断：这是个纯 CPU 负载，而且是轻量级的。2 核 4G 就绰绰有余，买 GPU 服务器纯属浪费。**

一个 2 核 4G 的机器跑 356 QPS，意味着它每天能扛 3000 万次请求 —— 给朋友试用、甚至给一个小产品用，都远远吃不完。

### 5.2 三档方案对比

| 方案 | 规格 | 年付 | **月均** | 适用 |
|---|---|---|---|---|
| ① 最省 | 轻量应用服务器 2核2G（200M 峰值带宽 / 40G ESSD） | 68 元（首年 38 元秒杀） | **≈ 5.7 元** | 个人试用、流量极小 |
| ② **推荐** | ECS 通用算力型 u1 **2核4G**（5M 带宽 / 80G ESSD Entry） | 199 元（企业认证）/ 955 元（标准价） | **≈ 16.6~79.6 元** | **本项目首选** |
| ③ 留余量 | ECS u1 4核8G | 652~955 元 | ≈ 54~80 元 | 以后要多容器 / 上监控 |
| ④ 别买 | 任何 GPU 实例（gn6i 起） | ≥ 15512 元 | ≥ 1293 元 | ❌ 纯 CPU 推理用不上 |

> 99 计划的「e 实例 2核2G 99 元/年（3M 带宽）」新老用户同享、续费同价，是性价比最高的入门选择，
> 但 2G 内存跑 ONNX + FastAPI 略紧（模型 90MB + 依赖 + 系统，实测常驻约 300~400MB，能跑但没余量）。
> **推荐 ②：2核4G，年付 199 元。**

### 5.3 附加项逐项认领

| 项 | 单价 | 本项目 | 说明 |
|---|---|---|---|
| **ACR 个人版** | **0 元** | **0 元** | 限额免费：3 命名空间 / 300 公开仓库 / 并发构建 1。**无 SLA，不能用于生产**，个人项目够用 |
| ACR 企业版基础版 | 需订阅 + OSS 存储/流量费 | 不用 | 要 SLA、要 P2P 分发、要漏洞扫描才需要 |
| 公网带宽 | 套餐内含 3~5M 固定带宽 | 0 元 | 超出部分按流量 0.8 元/GB |
| 云盘 | 套餐内含 40~80G ESSD Entry | 0 元 | 单独加：ESSD Entry 0.35~0.5 元/GB/月；**千万别用 PL1（1 元/GB/月）** |

## 7. 三个必须记住的省钱 / 防坑点

1. **不用时关机 ≠ 不收费。** 按量付费的 GPU 实例，仅"关机"仍然计算力费（资源还占着），
   必须**释放实例**才停。云盘更是无论开关机都在扣费。训练完记得释放，或者一开始就设"自动释放时间"。

2. **抢占式实例不能跑线上服务。** 价格能到按量的 1~2 折，但资源紧张时会被强制回收。
   只适合"能断点续跑的离线训练"——正好是你第二/四周那种 ablation 实验的场景。

3. **镜像体积直接等于钱。** 镜像越大：推送越慢、仓库存储费越高、服务器拉取越久、云盘占得越多。
   这就是为什么第六周的 Dockerfile 要分多阶段、要把 torch 的 CUDA 依赖挡在外面
   （3.2GB → 0.9GB，或干脆用 ONNX Runtime 的 0.25GB）。
